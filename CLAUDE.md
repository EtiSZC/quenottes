# Quenottes (formerly Brosse & Brille)

A playful PWA that guides children (ages 3–8) through a 3-minute tooth-brushing session with the mascot **Quenottes** (the little monster, formerly called Brillou; renamed everywhere in the app's text, alt texts, comments and `index.html` on 2026-10-28 — only older docs below, the `brillou`-free code names and a few CLAUDE.md sections still say Brillou). UI language is **French**. Originally scaffolded in Lovable (project `5e07ab90-e764-4e9b-8721-6225fc74815b`, "Sparkle Brush Buddy"), mirrored to the private GitHub repo `EtiSZC/quenottes-lovable` (then named `EtiSZC/quenottes`); now developed locally.

**Git:** this project's repo is `EtiSZC/quenottes` (public, remote `origin`; named `EtiSZC/brosse-et-brille` until 2026-10-21 — GitHub redirects the old name). Never push to or add `EtiSZC/quenottes-lovable` as a remote — it is the old Lovable mirror (it was called `EtiSZC/quenottes` until 2026-10-21), only a read-only source for binary assets.

**Website:** the presentation site lives in `site/`, which is its own git repo `EtiSZC/quenottes-site` (public, GitHub Pages from `main` /, custom domain **https://quenottes.site** via `CNAME`; domain bought at OVH 2026-10-21, DNS: apex A/AAAA → GitHub Pages IPs, `www` CNAME → `etiszc.github.io`). It is excluded from this repo via `.git/info/exclude`. Never give the user-site repo `etiszc.github.io` a custom domain: GitHub would move the app to that domain too (new origin → testers lose their localStorage).

## Commands

```bash
npm install
npm run dev       # http://localhost:8080
npm run build     # production build + PWA service worker (dist/)
npm test          # vitest (jsdom)
npm run lint
node scripts/screenshots.mjs [--quick]   # with dev server running: phone screenshots of every zone → screenshots/ (real time: ~3 min, --quick ~35 s)
```

Don't use Playwright's fake clock (`page.clock`) for visual checks: it desyncs framer-motion's `AnimatePresence`, so zone changes and the pause overlay don't render. Unit tests use vitest fake timers and are fine. The start button "breathes", so Playwright must click it with `{ force: true }`.

## Architecture

- `src/pages/Index.tsx` — state machine: `who` (picker, start screen when ≥ 2 profiles) → `home` → `brushing` → `celebration`, plus `album` and `parents`. On completion it calls `recordSessions()` (one entry per active child) and passes the results to the celebration.
- `src/components/BathroomBackground.tsx` — shared « Bain moussant » scene (soft mint gradient, no tile grid since phase 10; optional tint; 14 iridescent soap bubbles with fixed parameters that rise, sway, wobble and pop with a ring + droplets at their own height; foam). Every screen renders inside it.
- `src/components/AppTitle.tsx` — `APP_NAME` ("Quenottes") as a sticker title with tilted letters, on the home screen and the profile picker. Internal names stay: localStorage keys `brosse-brille:*` and the `BB1` sync prefix (renaming them would lose data / break older phones).
- `src/components/ToothpasteTipScreen.tsx` + `src/components/illustrations/ToothpasteQuantity.tsx` + `ToothpasteTubeIcon.tsx` + `src/data/toothpasteTip.ts` — « Le petit pois » (phase 11, merged into `main` on 2026-10-24): optional page reached by the round button at the bottom-left of Home (a pink flat toothpaste tube icon, no face; `onTip`, state `"tip"` in `Index.tsx`), never inside the brushing flow or after the celebration. **It plays by itself and nothing on it is touchable** (the mascot is a plain picture, the brush a `role="img"` scene; only ←, 🔊 and « Trop ? » are buttons): the mascot says the headline (`TIP_OPEN_LINE`) while the pink tube slides in from the top right; **when that voice ends** (`speak()` now returns a promise: true = sentence over — clip ended, or its estimated time passed when muted / device voice — false = cut off by a newer sentence or `stopSpeaking()`; muting mid-line lets the sequence move on) the tube squeezes twice and a slightly oval pea grows out of its nozzle, drops on the bristles (bounce, sparkles, brush squash, `playPop`), the tube leaves, then « Parfait ! Juste un petit pois. » and « Après, on crache, et c'est tout ! » follow one after the other, and « Trop ? » (oversized blob for 2.5 s, then the pea is back) is enabled. Stages `idle → arrive → squeeze → drop → leave` (`TipStage`); the sequence is cancelled on unmount / ← / tab hidden. Reduced motion: no tube, the pea fades in when the first voice ends. 4 clips in `TIP_VOICE_LINES` (spread into `VOICE_LINES`). `playClip(url, stillWanted, onEnded)` fires `onEnded` once on a natural end (plus a safety timer = duration + 1.5 s if the audio context stalls). No score, timer, red or ppm. The parents area shows a « Dentifrice : les repères » card (`PARENT_TIP`: pea from 3 years, spit don't rinse, read the label, HAS + ameli named as text, no outbound link). Sources HAS and ameli agree on the pea (3–6 years) and on spitting; they disagree on under-3s and fluoride ppm (HAS page cites AFSSAPS 2008: ≤ 500 ppm; newer UFSBD / Académie dentaire figures were only seen in search summaries), hence no ppm and no quantity under 3. **Copy to be read by a dentist or pharmacist before any release.**
- `src/components/HomeScreen.tsx` — sticker title, Brillou + speech bubble, `WeekCalendar` + streak, 📒 album button (top right, sticker-count badge), breathing 72px start button (`size="xl"`).
- `src/components/BrushingScreen.tsx` — timestamp-based timer (`Date.now()` deltas, survives pauses), zone via `getZoneAt()` and phase via `getPhaseAt()` (fractional seconds), pause overlay (✕ and ⏸ both open it; "Arrêter" there cancels), auto-pause on `visibilitychange`, Wake Lock. At 3:00 shows "Bravo, tout brille !" + sparkle wave for 1.8 s, then `onComplete` (once). Layout: small parent timer, `BubbleTimer`, `MouthDiagram` + `MiniMap`, Brillou + `SpeechBubble` with the phase instruction.
- `src/components/mouth/geometry.ts` — pure, unit-tested logic: smile view (10 teeth per arch: 3 molars, 4 front, 3 molars; molars have cusps), top-down arch view (`ARCH_TEETH`), `targetIndices`, `spotlightWindow`, `zoomViewBox` (1.9× on molars for "side" phases), `brushPlan`/`brushPosition` (ping-pong path across every target tooth, molars back→front), `isSurfaceShiny` (matte → shiny when the brush's first pass reaches a tooth).
- `src/components/mouth/MouthDiagram.tsx` — renders a step: `SmileView` (front / inside with see-through teeth and brush behind / zoomed molar side, zoom = animated SVG `viewBox`) or `ArchView` (top-down chewing surfaces); spotlight = ink veil 30% clipped to the mouth with a sliding window + sunshine corner frame; target teeth mint outline + glow + one "boing"; card-flip when the drawing changes; sparkle wave when finished.
- `src/lib/voice.ts` — Brillou's voice: `speak()` plays the pre-recorded ElevenLabs clip for that sentence (via `playClip` on the shared, tap-unlocked `AudioContext`); sentences without a clip fall back to `@capacitor-community/text-to-speech` (native Android TTS / browser `speechSynthesis`, fr-FR). Only the latest request may speak (`speechToken`); follows mute; `preloadVoice()` decodes all clips when brushing starts.
- `src/data/voiceLines.ts` — every sentence Brillou says (derived from the zone instructions + finish/celebration lines). `src/data/voice-manifest.json` maps each sentence to its clip in `public/voice/`.
- `src/lib/music.ts` — music mode, synthesized live (no files, no licence): 104 BPM xylophone/bass/strum/claps loop, C major for the upper teeth, F major + shaker for the lower teeth, a xylophone flourish at each step change, a finale in the last bar. `scoreEvents()` is a pure, tested score; `startMusic(fromSec)` / `stopMusic()` schedule it on the shared `AudioContext` following the session clock. **Levels (measured): voice ≈ −20.7 dBFS; music `MUSIC_LEVEL` 0.24 ≈ 12.5 dB under it, `MUSIC_DUCKED` 0.09 ≈ 21 dB under it while a voice clip plays** (via `subscribeClip`). A test guards these gaps. `renderMusic()` renders the same score to WAV for previews. Setting `brosse-brille:music`, **on by default**.
- `src/components/MusicButton.tsx` — 🎵 toggle next to 🔊 on the brushing screen.

- `src/components/SideMarker.tsx` — pulsing sunshine arrow on the edge of the screen for the side being brushed (back-teeth steps).
- `src/components/mouth/MiniMap.tsx` — tiny 2×3 map of the mouth showing the current area (dashed row = inside, ▲ = top).
- `src/components/BubbleTimer.tsx` — 8 bubbles in 2 groups of 4 (blue upper / peach lower) filling up, then a star. `role="progressbar"`.
- `src/components/CelebrationScreen.tsx` — brand-colour confetti, fanfare, Lily's "Bravo", new-sticker card (or stars + kind note if the slot was already filled), CTA "☀️ À ce soir !" (morning) / "🌙 À demain !" (evening) back to home, "📒 Mon album".

On-device history per child (localStorage `brosse-brille:progress:v2`: `profiles` [{id, name, avatar}], `data` per profile, `active` ids). Migrates the v1 single-child key on first run **without deleting it** (so the v0.5 APK still finds its data). Profiles: `addProfile` (max 4, 8 animal `AVATARS`), `updateProfile`, `deleteProfile` (never the last one), `setActiveProfiles`, `recordSessions` (brushing together: one slot + one sticker draw per child), `displayName` / `joinNames`. `recordSession` (morning < 14 h ≤ evening; one session and one random not-yet-earned sticker per slot), forgiving `streakOf` (≥ 1 slot per day; today not done yet doesn't break it), `weekOf` (Monday → Sunday), 20 `STICKERS` (never germ-themed) + 15 `HALLOWEEN_STICKERS` (`ALL_STICKERS`, `STICKER_SETS` = album pages). - `src/lib/sync.ts` — two-phone sync without backend: `encodeState()` → `BB1` + ASCII JSON (per child: id, name, avatar index, 2-bit/day bitmap of the last 400 days, 20-bit sticker mask `k` = the classics only (v0.8 phones refuse `k ≥ 2^20`), optional 15-bit Halloween mask `h` sent only when non-zero (older phones ignore unknown fields, so they lose nothing but don't receive Halloween stickers until updated); ~130 chars for 2 children, < 1 000 for 4 × 2 years), strict `decodeState()`, `suggestMatches()` (two passes: same id only if names agree or the local profile is unnamed, then normalized name; then take over an empty unnamed local profile, else add/ignore), `mergeState()` = union of brushings and stickers (never removes) — albums become the union of both phones, so the most complete album always wins and no sticker is lost; a `findLosses()` safety net makes `mergeState()` throw `SyncLossError` (nothing saved) if a merge would ever shrink an album or history; matched ids converge on the smaller one; an unnamed local profile takes the child's name/avatar, otherwise names/avatars and settings stay per phone; ids converge only if no other local child uses the target id (never onto the legacy `default`); deletions are not propagated. `suggestSameChild()` + `SameChildCard` (parents area) repair profiles left by the old bug (same name twice, or a "Moi" holding a child's stickers) with `mergeProfiles()` — union, nothing lost. The first fix (replace only a non-running context) did **not** cure it on the user's iPhone (2026-10-26): iOS can leave a context reporting `running` while mute. So the start tap and « Reprendre » now call `unlockAudio(true)`: always a brand-new context, plus a silent 1 s `<audio>` data-URI played in the tap to re-open the media session. Confirmed working on the user's iPhone (Chrome) on 2026-10-26.

## Product principles (keep)

- One tap to start, 3 minutes, 8 steps in order per arch: outside → inside → back teeth left (cheek side, then top) → back teeth right; upper then lower. No tongue step.
- Guidance must work for **pre-readers**: visual and audio first, text secondary.
- Screen is **propped on the sink, ~60 cm away**: large, glanceable elements.
- Mirror convention: screen-left = child's left.
- **Privacy**: no accounts, no tracking, no third-party SDKs; all data stays on device (COPPA / GDPR-K). Child profiles hold only a first name/nickname and an emoji avatar — no photo, age or surname. Two-phone sync goes QR → camera only (no network); the QR contains first names and history and is shown only in the parents area. **A sync never removes a sticker or a brushing**: albums and histories become the union of both phones; an ignored child leaves this phone untouched.
- **No dark patterns**: no ads, currency, loot boxes, guilt ("Brillou est triste"), streak punishment, or extra screen time after brushing. No scoring of brushing quality. Brushing twice in the same slot never earns an extra sticker; the end of a session points back to the next brushing ("À ce soir !"), not to more screen time.

## Roadmap (from design / PM / UX review)

2b. ✅ **Phone-test feedback** (done 2026-10-07, tag `v0.3-spotlight`):
   - **No germs.** Teeth go from matte cream `#F2EBDD` to shiny white + glint as the brush passes; sparkle wave over the whole mouth at the end.
   - **Spotlight** on target teeth: ink veil ~30% with a window around them, other teeth at 55% opacity, target bright white + solid 4px mint outline + glow, sunshine `#FFD23F` 4-corner frame, one-time "boing"; window slides between steps; no pulsing.
   - **Brush covers the whole zone**: travels across every target tooth (ping-pong) with the gesture on top — circles (front), flicks gum→tip (inner), scrub (molar cheek side), flat slide (molar tops).

   - **8 steps / 180 s**, same order per arch: Devant 22 s → Derrière (front + molars, inner side) 22 s → Fond gauche 23 s (cheek side 11 s, then top 12 s) → Fond droite 23 s; upper then lower. BubbleTimer: 8 bubbles in 2 groups of 4.
